# 工程设计与验证

## 为什么采用分阶段契约

继续训练可能同时发生父权重、学习率、数据增强、语言绑定和EMA策略变化。阶段契约将这些信息连同seen清单hash绑定到checkpoint，跨阶段只加载权重，同阶段才恢复优化器/调度器/随机数。恢复前跨rank汇总错误，避免一个rank拒绝而其他rank卡入DCP。

## 随机状态恢复

DataLoader的worker预取会推进随机数，恢复样本位置不足以恢复下一条增强/指令。项目保存worker Torch/Python/NumPy RNG状态，并在CPU小数据测试中比较不中断与恢复后的序列。GPU完整数值确定性并非该检查的承诺。

## EMA与导出

EMA按FSDP rank-local分片维护在CPU，减少GPU常驻内存。DCP保存EMA与更新步数；导出raw和EMA两份独立HF权重。推理选定其中一份，不进行多模型集成。

## 评测工程

- 显式GPU映射和服务就绪检查，避免模型仍在加载时烧掉任务重试。
- CPU线程上限控制，减少同机多server争用。
- clean/seen与randomized/unseen显式注入并在逐集记录中核对。
- 缩小episode数时保留100条描述生成规模，避免无意改变指令分布。
- 任务部分失败保留可见，不通过自动重跑覆盖已有结果。
- 新评测按randomized→clean顺序，训练与评测串行；发布脚本不停止其他用户进程。
